# 里程碑 8：游戏会话前后的存档备份

## 目标

实例包含本地世界时，MoyuMax 在创建游戏进程前和进程结束后分别生成一个完全本地、可验证的原子 ZIP 快照，并将结果关联到游戏会话。没有世界时记录“已跳过”而不生成空归档；启动前备份失败时不启动游戏；退出后备份失败不篡改真实游戏退出状态。

## 范围

1. SQLite 新增世界备份历史，记录实例、实例名、会话、触发原因、状态、世界数量、源大小、归档大小、路径、时间和错误。
2. 备份只读取实例 `.minecraft/saves` 下的真实本地目录，不跟随符号链接、junction 或其他重解析目标。
3. ZIP 先写入同目录临时文件，刷新后原子重命名；启动恢复时清理未提交临时文件并标记失败。
4. 同一会话的启动前和退出后备份分别幂等；游戏正常退出、异常退出和用户停止均执行退出后备份。
5. 启动器中断后重新打开时，为中断会话补写退出后备份；已有结果不得重复生成。
6. 默认每个实例保留最近 20 个成功归档，超额清理只触及受管备份根。
7. 会话摘要和数据页展示备份状态、触发原因、时间、世界数量和占用空间。

## 非目标

- 本里程碑不实现运行游戏期间的定时增量备份、用户自定义间隔和数量。
- 不实现世界级选择性回滚；后续里程碑将在回滚前自动创建当前恢复点。
- 不把备份同步到云端，也不读取回收站、共享仓库或托管 Java。

## 安全不变量

- 启动前备份失败时不得创建游戏进程。
- 任何备份都不得跟随链接离开世界目录，不得把令牌、账户数据或启动命令写入归档。
- 只有完成 ZIP 刷新与原子重命名后才能标记成功。
- 退出后备份失败只影响备份结果，不得把正常游戏退出改成崩溃。

## 验证

- Rust BDD 覆盖前后快照内容、无世界跳过、临时文件恢复、默认保留数量和路径边界。
- 启动生命周期 BDD 覆盖停止、正常退出、异常退出和启动器中断的备份关联。
- Playwright 覆盖首页会话摘要、数据页时间线、空状态和 200% 缩放。
- 全工作区 Rust、Clippy、格式、Svelte、Vitest、Playwright、生产构建与隔离 Release 启动通过。
