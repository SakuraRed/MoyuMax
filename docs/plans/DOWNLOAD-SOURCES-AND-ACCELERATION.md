# 下载来源统一与多线程加速计划

## 状态

planned。本文只定义后续实现边界，当前 M3 下载执行器尚未完成 MCI Mirror、BMCLAPI 和单文件多线程分段迁移。

## 用户结果

用户安装游戏、模组或整合包时，MoyuMax 自动选择可用来源，并在不突破全局限速和资源预算的前提下使用多线程分段下载提高大文件速度。暂停、断网、来源切换或应用重启后，只重下缺失或损坏的内容；最终文件仍必须经过完整校验和原子提交。

## 来源决策

1. 默认下载策略为“内置镜像优先”；用户仍可选择“官方源优先”或自定义源。
2. Modrinth 与 CurseForge 模组文件的内置镜像使用 MCI Mirror API：`https://www.mcimirror.top/`。
3. Modrinth 官方源继续保留。MCI Mirror 与 Modrinth 官方源可按用户策略和健康状态互相切换，任务详情必须记录真实来源。
4. CurseForge 官方下载源不接入。官方优先模式下遇到 CurseForge 文件时，界面必须显示“官方源不可用”，再提供 MCI Mirror 路径；镜像请求不得标记成官方直连。
5. Minecraft 游戏文件的默认镜像按 BMCLAPI 文档集成：`https://bmclapidoc.bangbang93.com/`，同时保留 Mojang 官方源。
6. 上述 URL 当前均可访问，但它们是服务或文档入口，不代表可以猜测固定 API 路径。实现前必须验证当前端点、响应 schema、校验值、Range、限流、缓存和服务条款。
7. provider 基址、能力和状态必须可替换、可测试；网络服务失效不能影响本地实例、内容索引、备份或游戏启动。
8. 当前 `ModrinthProvider` 直接使用官方 API v2，游戏文件使用 Mojang 官方链路，这是已验证的现状。迁移时保留其测试作为回归基线，不能在新镜像 provider 未通过真实契约测试前删除官方实现。

## 多线程下载范围

1. 保留现有跨文件并发，在单个大文件来源支持 HTTP Range 时增加分段并行下载。
2. 默认分段数由执行器根据文件大小、实时吞吐、延迟、磁盘压力、全局限速和来源错误率动态决定；用户只设置连接上限，不直接承担调参。
3. 初始实现建议每个大文件最多 8 个活动分段，所有任务仍受统一全局连接与内存预算约束。该值必须通过受控基准复核，不作为永远不变的协议常量。
4. 每个分段记录来源身份、字节范围、已完成长度、ETag 或 Last-Modified 等可用一致性证据。远端对象变化时废弃不再可信的分段。
5. 服务端忽略 Range、错误返回完整文件、分段交叉或总长度变化时，停止并行合并，安全降级为单连接续传；无法续传时只清理该文件的暂存内容后重下。
6. 分段合并后执行完整大小与 SHA-1、SHA-256、SHA-512 等计划提供的可信哈希校验。没有通过最终校验的文件不能进入共享存储或实例。
7. 暂停和重启恢复不自动联网；沿用现有恢复确认语义。用户拒绝恢复时清理该任务分段，不触及已提交数据。
8. 任务详情展示平滑速度、预计时间、有效连接数、分段状态、来源切换和降级原因。

“多线程下载”是用户可理解的产品名称。Rust 实现可以采用异步 Range 请求和有界工作池，不要求为每个分段创建独立操作系统线程。

## 性能与资源验收

- 在受控 Range 测试源、同一文件和同一网络条件下，分段模式进行至少 3 轮对照；当单连接未占满可用链路时，中位吞吐应有可测提升，目标不低于单连接的 1.8 倍。
- 如果单连接已经达到链路或磁盘瓶颈，执行器应减少分段，不能为追求线程数制造额外资源占用。
- 下载缓冲必须有全局硬上限，不随任务数和分段数无界增长；具体上限在实现计划中结合启动器 256 MiB 前台硬门复核。
- 分段调度不得持续阻塞 UI、SQLite 写事务、游戏日志处理或正在运行的 Minecraft。
- 限速启用时，多线程总速度不得系统性突破用户上限。

## 安全不变量

- 不绕过来源身份验证、访问限制、许可证或服务条款。
- 不把 MCI Mirror 表述为 Modrinth 或 CurseForge 官方源。
- 不因追求速度降低哈希、大小、ZIP 路径或原子提交验证。
- 不把分段写到任务暂存区之外，不覆盖同名异哈希用户文件。
- 来源切换必须记录；自定义源失败时仍禁止静默切换。
- 任何失败都不得破坏已验证共享文件、已安装实例或其他任务的暂存区。

## BDD 与测试计划

实现前新增独立 Gherkin 和 eval，至少覆盖：

1. 支持 Range 的大文件产生多个不重叠请求，合并后与可信哈希一致。
2. Range 被忽略时不把完整响应追加到已有分段，并安全降级。
3. 某一分段损坏时只重试该分段，最终校验失败时不提交。
4. 暂停、应用重启和用户同意恢复后复用有效分段。
5. ETag、总长度或来源对象变化时废弃旧分段。
6. 全局限速、连接上限和两个并行任务之间保持公平。
7. 默认策略将 Modrinth 与 CurseForge 镜像下载路由到 MCI Mirror，并保留真实来源标签。
8. Modrinth 官方优先模式可以直连官方源，镜像失败时也能按策略回退到官方源。
9. CurseForge 官方源选项展示不可用，不发起官方直连。
10. 默认策略将 Minecraft 游戏文件路由到 BMCLAPI 镜像，官方优先或镜像失败时保留 Mojang 官方路径。
11. Minecraft 镜像端点严格按当前 BMCLAPI 文档解析。
12. MCI Mirror 或 BMCLAPI 离线时，本地内容管理和游戏启动继续可用。

## 非目标

- 本计划不实现未经用户选择的模组安装或自动更新。
- 不承诺 MCI Mirror 未公开或未验证的搜索、账户、上传能力。
- 不通过无限连接、禁用 TLS、跳过校验或隐藏来源切换来制造速度指标。
- 不在本计划中实现 P2P、局域网缓存服务器或 CDN 运维。
