# 里程碑 2：第一个游戏安装计划与持久化队列

## 用户结果

用户从首页空状态进入“新建实例”，接受推荐稳定版与兼容 Fabric 后，可以创建一个真实、可重启恢复的安装任务。该里程碑不伪造下载进度；任务执行器未接管的阶段明确显示为排队。

## 当前交付边界

1. 从 Mojang 官方版本清单读取稳定版与历史版本，并将最近一次成功结果缓存到 SQLite。
2. 读取所选版本的官方元数据，解析 Java 主版本、客户端、库、资源索引和日志配置下载项。
3. 查询与所选游戏版本兼容的 Fabric Loader 版本，只显示兼容项。
4. 生成版本化安装计划，默认完全隔离，并把共享基础文件映射到全局受管存储。
5. 在同一事务中创建安装任务及计划快照；任务重启后保持可恢复状态。
6. 用“发行版、完整构建、架构”唯一键复用托管 Java；删除实例不删除 Java。
7. 为每项安装任务创建独立暂存区；实例只有在后续校验与提交完成后才进入可启动列表。
8. 按 `inst-new-default` 和 `inst-new-confirm` 实现声明式新建实例页，并从首页主操作进入。

## 明确不伪造的能力

- 本里程碑建立真实下载清单和任务状态，不把计时器动画当作下载。
- Forge、NeoForge、Quilt 的提供方接口保留在加载器模型中，但未接入前不得显示为可安装。
- 文件传输、SHA-1 校验、Fabric Profile 合并、Java 解包和最终原子提交由紧随其后的任务执行器增量完成。

## 领域不变量

- 在线元数据请求不能阻塞应用首屏。
- UI 不直接写 SQLite、实例目录或受管存储。
- 任务计划保存创建时的解析结果，后续目录更新不能悄悄改变已确认任务。
- 运行中任务在进程重启后只进入等待恢复确认，不自动联网。
- 未提交任务不能产生可启动实例记录。
- 同一托管 Java 完整构建在数据库和磁盘布局中均只有一份逻辑身份。
- 所有可共享 Minecraft 文件进入全局受管存储；实例可变数据保持隔离。

## 验证

- Rust BDD 测试覆盖安装计划、Java 去重、任务重启恢复、暂存隔离和元数据缓存。
- 前端单元测试覆盖默认选择、名称派生和确认摘要。
- Playwright 覆盖首页进入、默认配置、确认、真实排队状态、960×600 与 200% 缩放。
- Tauri 真实运行验证官方元数据请求、SQLite 持久化和重启后的任务可见性。
