# 里程碑 14：任务控制完整化

## 目标

用户可以对单个任务暂停与恢复、调整队列优先级、设置全局下载限速，并由系统依据网络状况自动收缩并发连接。所有控制与 M9 全局暂停、M10 分段下载语义一致：任何控制都不破坏续传、校验与原子提交。

## 范围

1. 单任务暂停/恢复：执行中的任务在分段边界中断进入 `paused`；排队任务标记 `paused` 不参与调度；恢复单个任务重新入队。与全局暂停互不干扰：全局恢复只恢复被全局暂停打断的任务，用户单独暂停的任务保持暂停。
2. 优先级：任务具有持久化优先级（默认 0，可升降），共享执行槽按优先级与创建时间出队；界面支持排队任务上移/下移。
3. 全局限速：持久化的字节/秒上限（0 为不限速）；所有下载连接（含分段）共用同一令牌桶，实测总吞吐不系统性突破上限；任务详情显示限速状态。
4. 压力感知并发：下载器按滚动窗口测量每连接吞吐与失败率，吞吐显著劣化或连续失败时收缩有效连接数（下限 1），恢复后缓慢回升；任务详情显示有效连接数。本里程碑的压力信号仅来自网络行为（吞吐与失败），磁盘与 CPU 压力感知属后续。
5. schema v10：任务表增加优先级列。

## 非目标

- 不实现计划时段下载、磁盘与 CPU 压力感知、按来源限速。
- 不改变 M9 退出保护语义与 M3/M10 恢复语义。

## 安全不变量

- 任何暂停都在分段边界中断，保留 `.partial` 与分段清单，不产生 `failed`。
- 限速全局共享：分段下载不得通过增加连接数系统性突破用户上限。
- 优先级只影响出队顺序，不影响校验与提交。
- 压力调节只收缩与缓慢恢复连接数，不跳过校验。

## 验证

- Rust BDD：单任务暂停/恢复、与全局暂停的组合语义、优先级出队顺序、令牌桶限速实测（总吞吐 ≤ 上限 ×(1+10%)）、压力收缩与恢复、有效连接数记录。
- Playwright：任务行单任务暂停/恢复、优先级调整、限速设置与展示、960×600 与 200% 缩放。
- 全工作区 Rust、Clippy、格式、Svelte、Vitest、Playwright、生产构建与 NSIS 构建通过。
