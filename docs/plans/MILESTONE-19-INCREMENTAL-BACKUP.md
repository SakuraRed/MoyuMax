# 里程碑 19：运行期间增量备份与世界历史

## 目标

游戏运行期间按可配置间隔自动创建增量备份，只保存相对上次备份变化的文件；备份保留数量可配置且清理不破坏恢复链；回滚可落到任一增量点，恢复语义与 M8 全量快照一致。

## 范围

1. 备份类型：`full`（现有语义）与 `incremental`；增量备份只包含相对基准新增/变化的文件，并记录删除清单；`base_backup_id` 链接到上一次 ready 备份形成恢复链。schema v14。
2. 变更检测：新备份的 manifest 写入完整文件索引（路径、大小、mtime）；创建增量时读取基准 manifest 对比，无可用索引时回退为全量。
3. 定时调度：会话运行期间按 `world_backup_interval_minutes`（默认 30 分钟，0 关闭）创建定时备份；会话结束或启动器退出后调度停止；调度失败只记录不阻断游戏。
4. 保留策略：`world_backup_keep_count`（默认 20，1–100）；清理最旧备份时级联删除以其为基准的增量链段，恢复链不得悬空。
5. 回滚扩展：回滚到增量点时按链依次应用全量与各增量（含删除清单），结果与该时点状态一致；恢复点语义沿用 M17。
6. 前端：备份时间线显示类型（完整/增量）与"定时"触发标签；设置页新增备份间隔与保留数量。

## 非目标

- 不实现块级（二进制差分）增量；文件级粒度足够。
- 不实现跨实例共享去重。
- 不改变 M8 启动前/退出后全量备份语义。

## 安全不变量

- 增量恢复结果必须与该时点的 saves 状态逐文件一致（含已删除文件不再出现）。
- 清理不得在恢复链中留下指向不存在基准的增量。
- 定时备份失败不得影响游戏会话；写入仍走 partial + 原子改名。
- 调度只在会话运行期间进行，启动器退出后不产生新备份任务。

## 验证

- Rust BDD：增量只含变化文件、删除清单、链式回滚逐文件一致、基准缺失回退全量、链感知清理、间隔/保留配置持久化与边界、会话结束调度停止。
- Playwright：类型徽章、定时标签、设置项、960×600 与 200% 缩放。
- 全工作区 Rust、Clippy、格式、Svelte、Vitest、Playwright、生产构建与 NSIS 构建通过。
