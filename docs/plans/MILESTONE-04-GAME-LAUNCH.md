# 里程碑 4：真实游戏启动与进程生命周期

## 用户结果

首页展示已经安装的实例。用户点击启动后，MoyuMax 在本地完成完整性检查，以稳定的本地离线身份展开 Mojang 与 Fabric 参数，启动托管 Java，并持续记录进程状态与日志。关键文件缺失时不会创建残缺进程；非零退出会成为可诊断失败。

## 实现范围

1. 从 SQLite `instance_runtime` 读取版本化运行时清单，并与实例内清单交叉校验。
2. 校验托管 Java、classpath、资源索引、日志配置、实例工作目录和原生库机制。
3. 按 Windows x64 与功能开关展开 Mojang `arguments.jvm`、`arguments.default-user-jvm`、`arguments.game` 与 Fabric 参数。
4. 展开 classpath、assets、natives、账户、版本、日志和启动器占位符；拒绝未知占位符。
5. 使用稳定的本地离线身份实现首版完全离线启动，不伪装微软在线账户。
6. 将 stdout、stderr、真实退出码和会话状态写入实例日志与 SQLite。
7. 同一实例只允许一个运行会话；支持用户主动停止。
8. 首页展示实例、启动状态、启动和停止操作，不阻塞 Tauri UI 线程。

## 不变量

- 不持久化或输出明文访问令牌与未脱敏完整命令。
- 启动参数引用的本地路径必须位于实例目录或受管共享存储内。
- 完整性检查失败不得创建 Java 进程。
- 启动器异常退出后，遗留的 `starting` 或 `running` 会话必须在重启时标记为中断。
- 新版原生 JAR 保留在 classpath，旧式原生分类器使用安装阶段预解包目录。
- 游戏退出不删除实例、Java、共享文件或用户存档。

## 后续衔接

崩溃诊断包直接消费启动会话、stdout、stderr、游戏日志和脱敏启动摘要；正式微软账户接入只替换账户上下文，不改变参数展开与进程管理边界。

## 验证结果

- 14 个核心 BDD 回归覆盖参数、文件完整性、受管目录、x64 native、重复启动、停止、重启恢复、日志和失败状态。
- Tauri 使用异步启动检查和后台进程协调器，启动命令不会占用 UI 线程；停止请求按实例路由。
- 声明式首页在有实例时显示 Minecraft、加载器、本地离线身份和真实会话状态，960×600 与 200% 放大无重叠。
- 当前推荐 Minecraft 26.2、Fabric 0.19.3、Azul Zulu 25.0.4+7 的从空安装探针和真实游戏启动探针均通过。
- 真实 stdout 包含 `Loading Minecraft 26.2 with Fabric Loader 0.19.3`，游戏完成 Windows x64 native 自解包后由显式停止请求结束，会话状态为 `stopped`。
