# 里程碑 17：世界存档管理

## 目标

用户可以按实例查看世界存档清单、导入导出世界，并把实例的世界回滚到任一已完成备份；回滚前自动创建恢复点备份，任何失败都能回到回滚前状态。

## 范围

1. 世界清单：按实例列出 `.minecraft/saves/` 下的世界（名称、占用、level.dat 最近修改时间）。
2. 世界导出：把单个世界目录打包为 ZIP（`<世界名>/...` 布局）写入用户选择的位置。
3. 世界导入：校验 ZIP 条目安全（拒绝路径穿越），识别根级 `level.dat` 或单一顶层目录布局；同名世界拒绝导入；经受管暂存与原子 rename 进入 saves。
4. 备份回滚：选择任一 `ready` 状态备份 → 先创建恢复点备份（手动触发，记录当前 saves）→ 解压备份到实例内暂存 → 原子交换 saves 目录 → 清理；失败时回到回滚前 saves；重启后收敛未完成的交换。
5. 前端：数据中心新增"世界存档"区（实例选择、世界清单、导入/导出），备份时间线提供带回滚确认对话框的回滚入口。

## 非目标

- 不实现按世界粒度的备份（M8 备份单位为整个 saves）。
- 不实现世界删除与回收站扩展（随 M18 截图管理统一设计）。
- 不实现运行期间定时增量备份（缺口 #8 后续）。

## 安全不变量

- 回滚前必须先成功创建恢复点备份；恢复点创建失败则中止回滚。
- 解压任何 ZIP 都必须校验条目路径，拒绝穿越与绝对路径。
- 交换中断后重启必须收敛：要么完成交换，要么回到原 saves，不得丢失两侧目录。
- 导入不覆盖既有世界；导出写到用户明确选择的位置。

## 验证

- Rust BDD：世界清单、导出可再导入、导入布局识别与同名拒绝、回滚成功路径（saves 内容回到备份状态且恢复点存在）、恢复点失败中止、解压校验、中断交换重启收敛。
- Playwright：世界清单、导入/导出流程、回滚确认对话框、960×600 与 200% 缩放。
- 全工作区 Rust、Clippy、格式、Svelte、Vitest、Playwright、生产构建与 NSIS 构建通过。
