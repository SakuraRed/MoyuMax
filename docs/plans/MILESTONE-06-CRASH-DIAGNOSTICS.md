# 里程碑 6：本地崩溃诊断与脱敏导出

## 用户结果

游戏异常退出或启动器在游戏运行期间中断后，MoyuMax 自动生成完全本地的崩溃报告。用户从首页进入崩溃页，先看到通俗摘要、可能原因和证据，再决定是否预览并导出脱敏诊断包。任何内容都不会自动上传，也不会擅自修改实例配置或安装模组。

## 实现范围

1. 失败与中断的启动会话自动生成一份幂等崩溃报告；正常退出和用户主动停止不生成报告。
2. 报告聚合游戏最后输出、`latest.log`、`debug.log`、原生崩溃文本、MoyuMax 会话日志和脱敏启动脚本。
3. 使用本地规则识别内存不足、模组冲突、Java 或原生崩溃以及启动器中断；未知原因保持诚实，不伪造结论。
4. 报告索引写入 SQLite，结构化 `report.json` 通过暂存目录原子发布；重复恢复不会创建重复报告。
5. 诊断包导出采用“预览清单与脱敏摘要 -> 用户确认 -> 写入本地 ZIP”的两阶段流程。
6. 导出时对玩家名、账户标识、用户目录、IP 或服务器地址、令牌、密码和 Authorization 字段进行脱敏，并限制单项日志大小。
7. Tauri 只适配报告读取、导出预览和确认命令；Svelte 崩溃页保持声明式，覆盖摘要、证据、隐私说明、预览、成功与失败状态。
8. 浏览器测试运行时提供纯本地确定性数据，不执行上传或伪造文件系统导出。

## 不变量

- 默认离线，里程碑内不存在上传命令、遥测或远程崩溃服务。
- 原始日志保持原位；诊断生成和导出不得修改实例、模组、配置、存档或启动会话。
- 诊断 ZIP 只能写入 MoyuMax 受管的本地导出目录，使用临时文件和原子重命名。
- 公开报告和 ZIP 不包含原始受管路径、玩家名、账户标识、令牌、密码或服务器地址。
- 自动规则只给出依据与建议，不自动应用修复；未来授权修复必须另行创建恢复点。
- 报告生成失败不得把已经持久化的游戏退出状态改写为正常退出。

## 验收

- Rust BDD 证明失败报告生成、幂等恢复、证据发现、规则分析、脱敏和 ZIP 原子导出。
- 现有启动生命周期 BDD 继续通过，并证明失败会话拥有报告、正常和主动停止会话没有报告。
- Playwright 证明用户必须先看到文件清单与脱敏摘要，随后才能确认本地导出。
- 960×600 与 200% 放大下崩溃页无横向溢出、文本贴边或主操作遮挡。

- 内存不足、模组冲突、Java、原生崩溃、启动器中断和未知原因的本地规则。
- 报告目录与 ZIP 的暂存、刷新、原子发布及失败清理。
- 报告生成与导出时双重脱敏，单项文本保留末尾 512 KiB。
- Tauri 预览 ID 门禁、声明式崩溃页、本地导出结果和浏览器 E2E 运行时。
