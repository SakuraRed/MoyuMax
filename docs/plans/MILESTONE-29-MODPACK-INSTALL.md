# 里程碑 29：Modrinth 与 CurseForge 整合包安装与更新

## 目标

用户可以直接导入 Modrinth（.mrpack）与 CurseForge（.zip）整合包创建实例，并用同格式的新版整合包对已安装实例做文件级更新；全程哈希校验、原子提交、失败回滚，绝不执行整合包内任何脚本。

## 范围

1. 格式解析与预览：
   - Modrinth `modrinth.index.json`（formatVersion=1）：名称、版本、游戏/加载器依赖、文件清单（路径、双哈希、大小、下载地址）。
   - CurseForge `manifest.json`：名称、版本、游戏版本与主加载器、文件清单（projectID/fileID）；CF 文件下载地址经 MCI Mirror 解析，SHA-1 校验；`overrides/` 目录安全解包。
2. 安装：先按包依赖创建游戏实例（复用既有安装管线），再下载全部包文件（哈希校验、镜像策略沿用 M10）并原子提交到实例目录；任何失败回滚到安装前状态；中断后重启收敛。
3. 更新：对同一实例导入同格式新版包——按安装时受管清单计算差异：旧包有而新包无的文件在未被用户改动时删除，变化的文件替换，用户改动过的文件保留并汇总提示；游戏版本或加载器不一致时拒绝并说明。
4. 实例记录：schema v16 `instance_modpacks`（来源、名称、版本、受管文件清单、安装时间）；实例卡显示整合包徽章；不追踪在线包版本（在线更新检查属后续）。
5. 进度：异步命令经进度事件回报当前文件/总数；打包过程不阻塞界面其他操作。

## 非目标

- 不执行整合包内任何脚本或安装器（.mrpack/.zip 均为纯声明式数据 + 文件）。
- 不做整合包在线浏览、搜索或自动更新检查。
- 不做实例内模组逐项与包文件的冲突仲裁（更新只按受管清单与用户改动判定）。
- 不做导出整合包。

## 安全不变量

- 只走声明式解析与文件下载，绝不执行包内代码；overrides 解包必须校验路径穿越。
- 安装/更新失败完整回滚；中断重启后不留半成品。
- 用户改动过的受管文件在更新时不被覆盖。

## 验证

- Rust BDD：两种格式解析、预览、安装原子提交与失败回滚、更新差异（删除/替换/保留用户改动）、游戏版本不一致拒绝、overrides 穿越拒绝、中断收敛。
- Playwright：导入预览、安装进度、包徽章、更新差异提示、960×600 与 200% 缩放。
- 全工作区 Rust、Clippy、格式、Svelte、Vitest、Playwright、生产构建与 NSIS 构建通过。
