# 里程碑 25：启动器更新检查与安全下载

## 目标

用户可以手动检查启动器更新、查看新版本信息、下载安装包并经 SHA-256 校验后自行安装；数据兼容检查阻止跨越最低支持版本的更新；卸载默认保留全部个人数据。

## 范围

1. 更新检查：`updates.rs` 的 UpdateClient（GitHub Releases API），比较当前版本（`CARGO_PKG_VERSION`）与最新发布（含 prerelease 规则）；手动触发，不做后台自动检查。
2. 更新设置：`update_checks_enabled` 持久化（默认开启，仅控制提示，不产生自动下载）；设置页更新区提供检查入口、当前版本与结果展示。
3. 安全下载：下载选定的安装包到受管 `updates/` 目录，按发布资产摘要校验 SHA-256 与大小；校验失败删除文件并给出可读错误；不提供任何自动安装。
4. 数据兼容：发布说明中的 `moyumax-min-app-version: x.y.z` 声明最低可升级版本；当前版本低于该值时阻止下载并说明。
5. 卸载保留：NSIS 卸载不删除任何应用数据（Tauri 默认行为），由安装器契约测试锁定；文档明确保留范围（实例、存档、备份、账户与 JDK）。
6. 打开方式：下载完成后仅提供“打开所在位置”，由用户自行运行安装包；失败回滚路径为重新安装旧版本安装包（数据不动）。

## 非目标

- 不实现自动下载、自动安装或后台定期检查。
- 不实现 Authenticode 验证（缺口 #13 后半）。
- 不实现卸载数据分类选择向导（正式版项；当前默认全保留）。

## 安全不变量

- 更新下载必须经 SHA-256 校验；校验失败不得保留文件。
- 任何安装动作必须由用户在 MoyuMax 之外自行触发。
- 更新检查失败（网络/解析）不影响本地功能。

## 验证

- Rust BDD：版本比较（含 prerelease）、检查解析、最低版本阻断、下载校验与失败清理。
- Playwright：更新区渲染、检查结果、下载状态、960×600 与 200% 缩放。
- 安装器契约测试继续通过（卸载不删除数据）。
- 全工作区 Rust、Clippy、格式、Svelte、Vitest、Playwright、生产构建与 NSIS 构建通过。
