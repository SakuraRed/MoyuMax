# MoyuMax UI/UX 需求书

> 文档版本：0.1.0
> 状态：产品基线，待 mockups 映射
> 目标平台：Windows 10 22H2 及以上，x64
> 首发形态：传统每用户 EXE 安装器，常驻托盘，不要求管理员权限
> 产品许可：GPL-3.0-only
> 最后更新：2026-07-22

## 1. 文档目的

本需求书定义 MoyuMax 的用户目标、信息架构、页面职责、交互行为、状态反馈、无障碍要求和 BDD 验收基线。视觉风格、排版细节、布局比例和品牌表达由后续 mockups 决定。

本需求书与 mockups 的职责边界如下：

- 本文回答“用户能做什么、系统如何反馈、失败后如何恢复、怎样才算验收通过”。
- mockups 回答“信息如何组织、控件如何呈现、品牌和视觉层级如何表达”。
- mockups 不得省略本文要求的关键状态、风险提示、撤销入口、键盘焦点和无障碍语义。
- 若 mockups 与安全、可恢复性、无障碍或性能预算冲突，应在设计评审中显式解决，不得静默选择其一。

## 2. 产品定位

MoyuMax 是一款面向 Minecraft Java Edition 的安装式统一管理应用。它不是单文件启动器，而是覆盖环境部署、游戏安装、模组生态、实例维护、故障诊断和数据恢复的本地管理平台。

核心承诺：用户不需要理解 Java、加载器、依赖树、文件目录和启动参数，也能安装并运行游戏；高级用户仍可查看、覆盖和调试每一层配置。

### 2.1 核心体验原则

1. 零门槛：默认路径应能直接工作，不把 Java、文件布局或兼容性决策推给普通用户。
2. 快速可感知：窗口应立即出现，在线数据和后台检查不得阻塞主界面。
3. 安全默认：实例默认隔离、自动更新默认关闭、危险网络能力默认关闭。
4. 可恢复：安装、更新、迁移、删除和 CLI 写操作都必须可以回滚或恢复。
5. 渐进披露：默认界面只显示完成任务所需的信息，诊断和精细控制放入展开区或高级设置。
6. 统一状态：GUI、CLI、托盘和后台任务展示同一事实，不允许出现互相矛盾的进度或配置。
7. 完整离线：本地实例、账户令牌、备份、日志和管理功能不依赖 MoyuMax 云服务。
8. 尊重用户：不擅自安装模组、不擅自修改用户配置、不默认开启遥测或公网监听。

### 2.2 用户体验成功标准

- 新用户使用默认选项完成首次安装时，不需要打开文件资源管理器、命令行或 Java 官网。
- 除登录流程外，从“安装新游戏”到任务开始最多需要 3 次主要决策。
- 所有超过 1 秒的操作都有明确状态；所有超过 10 秒的操作都可在任务中心查看。
- 可恢复操作优先提供“撤销”或“恢复”，危险的永久操作必须说明影响对象。
- 错误信息同时包含：发生了什么、哪些数据受影响、用户现在能做什么。

## 3. 用户类型与核心任务

### 3.1 初次接触 Minecraft 的用户

目标：登录、选择游戏版本、等待安装、开始游戏。

要求：默认推荐稳定版本、自动选择 Java、自动选择兼容加载器版本、提供通俗错误解释，不展示不必要的路径和 JVM 术语。

### 3.2 普通模组玩家

目标：创建相互隔离的实例，从 Modrinth 安装模组与整合包，管理更新、依赖和存档。

要求：清楚显示内容兼容性、来源、实例影响范围和更新变更；自动处理必需依赖，可选依赖由用户决定。

### 3.3 高级玩家与整合包作者

目标：控制加载器、Java 补丁版本、JVM 参数、内容锁定、导入导出、日志和启动命令。

要求：高级控制可发现但不干扰默认流程；强制操作经风险提示后允许继续。

### 3.4 维护者与自动化工具

目标：通过版本化 CLI 创建和检查实例、解析依赖、生成整合包、读取任务进度。

要求：CLI 与 GUI 共用后台核心、事务、验证和回滚；不得读取凭据、永久删除数据或修改安全设置。

## 4. 发布范围

### 4.1 首个公开预览版

首个公开预览必须形成以下完整闭环：

- 每用户安装、卸载、更新提示、托盘常驻和快速唤醒。
- Microsoft、离线、Authlib Injector、LittleSkin、统一通行证账户入口。
- Vanilla、Forge、NeoForge、Fabric、Quilt 的安装与启动。
- Azul Zulu 托管 Java 的自动选择、安装、去重和环境管理。
- 实例默认完全隔离，共享可校验重建的基础文件。
- 统一持久化任务队列，自动依据网络、磁盘和 CPU 压力控制并发，并支持暂停、恢复、优先级、限速和失败恢复。
- Modrinth 搜索、安装、依赖解析、版本锁定和按实例更新策略。
- 模组、资源包、光影、数据包、世界存档和截图管理。
- 存档备份、历史回滚、内置回收站、日志控制台和崩溃诊断。
- 简体中文、繁体中文、英文，主题、缩放、键盘和屏幕阅读器支持。
- 开发者模式下的内置 CLI。

Microsoft 登录若尚未完成项目名义的应用注册，则不得将该构建标记为公开预览版。

### 4.2 第二个公开版本

- 从其他启动器迁移实例、设置和来源格式允许迁移的现有令牌。
- 迁移数据始终复制到 MoyuMax 托管仓库，来源目录始终保留。
- 完善 MoyuMax 原生整合包格式，并覆盖 CurseForge、Modrinth、MultiMC/Prism、MCBBS、HMCL 服务器格式和 PCL 格式的导入导出。

### 4.3 后续范围

- macOS、Linux 原生桌面支持。
- 经授权后启用 CurseForge；首个预览只启用 Modrinth，但保留 provider 接口。
- 端到端加密云同步、助记词恢复和可选付费云服务。
- P2P 建房、服务端管理、第三方可执行插件。
- Cleanroom、LegacyFabric、LiteLoader、OptiFine、OptiFabric 等扩展加载器支持。

未实现的后续功能不应占据主导航或制造“功能很多但不可用”的印象；只在相关入口附近以非打扰方式说明路线图。

## 5. 信息架构

### 5.1 一级导航

1. 首页：最近实例、主要启动操作、活动任务和需要处理的问题。
2. 实例：所有实例的浏览、筛选、创建、分组和批量管理。
3. 资源：Modrinth 内容发现、搜索、详情和安装目标选择。
4. 任务：所有安装、更新、迁移、校验、备份和下载任务。
5. 数据：备份、回收站、存储位置和迁移。
6. 设置：通用、下载、来源、账户、Java、外观、网络、无障碍、开发者和关于。

账户切换、全局搜索、任务状态和网络状态属于应用级工具，不作为重复的一级页面。

### 5.2 实例详情导航

- 概览：启动、版本、加载器、默认账户、最近运行、健康状态。
- 内容：模组、资源包、光影和数据包。
- 世界：存档、备份、导入、导出和回滚。
- 截图：浏览、筛选、复制和打开本地位置。
- 日志：实时输出、历史会话、崩溃报告和诊断。
- 设置：隔离、Java、内存、窗口、参数、更新、备份和高级配置。

### 5.3 全局搜索

全局搜索用于快速定位实例、已安装内容、设置项和本地诊断报告。首版不把远程 Modrinth 搜索混入全局搜索，以避免网络延迟和结果语义混淆；远程内容由“资源”页面搜索。

## 6. 应用外壳与全局交互

### 6.1 启动与唤醒

- 启动后先呈现可交互外壳，再异步刷新账户、资源和更新状态。
- 不显示阻塞式启动动画；必要时使用稳定布局的骨架占位。
- 托盘唤醒应恢复上次页面和滚动位置，但敏感明文页面必须回到遮罩状态。
- UI 关闭后允许销毁完整界面，仅保留轻量后台核心和托盘。

### 6.2 关闭窗口

首次关闭窗口时弹出选择：

- 最小化到系统托盘。
- 退出 MoyuMax。
- 记住本次选择。

托盘右键菜单至少包含：显示 MoyuMax、最近实例快速启动、活动任务摘要、暂停全部任务、退出。

若存在未提交事务或正在运行的游戏，退出前必须说明影响；可安全转交给后台的任务不应被无故取消。

### 6.3 全局通知

- Toast：轻量成功、撤销入口、非关键状态变化，自动消失且可键盘访问。
- Banner：离线、存储离线、更新可用、空间不足等持续状态，直到问题解除或用户明确忽略。
- Modal：只用于不可逆操作、风险授权、凭据输入、冲突决策和阻塞性失败。
- 系统通知：仅用于用户离开窗口后仍值得知道的任务完成、失败、游戏崩溃和备份异常。

同一事件不得同时以多种方式重复打扰用户。

### 6.4 导航保护

- 页面切换不取消后台任务。
- 未保存的表单离开前提示保存、放弃或继续编辑。
- 弹窗关闭后焦点返回触发控件。
- 浏览器式后退只改变页面层级，不撤销数据操作。

## 7. 页面与功能需求

### 7.1 首次运行与按需引导

首次运行仅收集完成启动所需的信息：语言、数据位置和基础隐私选择。其余能力在首次使用时按需解释。

默认值：

- 语言跟随系统，无法匹配时使用简体中文。
- 主题跟随系统。
- 数据默认位于 MoyuMax 安装目录下的 `data` 子目录，之后可一键分离或迁移。
- 启动器只自动检查并提示新版本，下载与安装必须由用户手动触发。
- 诊断与遥测不上报。
- 实例隔离开启。

引导必须允许跳过非必要步骤，并支持之后从设置重新查看。

### 7.2 首页

首页首要任务是“继续游戏”，而不是展示资讯。

首页应包含：

- 最近使用或用户固定的实例主卡片。
- 明确的“启动”主操作及临时账户切换入口。
- 无实例时的单一主操作“安装第一个游戏”。
- 活动任务的精简进度；点击进入任务中心。
- 需要处理的问题，例如存储离线、环境缺失、更新冲突或上次崩溃。
- 最近一次游戏会话摘要，包括时长、退出状态和备份结果。

不得默认加载新闻流、远程图片或会拖慢首屏的营销内容。

### 7.3 实例列表

实例卡片至少展示名称、Minecraft 版本、加载器、状态和主要操作。列表支持搜索、按最近运行或名称排序、按加载器和健康状态筛选。

实例状态统一为：

- 可启动。
- 正在运行。
- 正在维护。
- 需要处理。
- 存储离线。
- 已损坏但可修复。

批量操作只对选择集显示。批量删除、移动或更新前必须展示逐实例影响摘要。

### 7.4 新建与安装实例

默认流程采用单页渐进式配置：

1. 选择 Minecraft 版本或接受推荐稳定版。
2. 可选选择加载器和整合内容；系统只呈现兼容版本。
3. 确认名称、位置和预计空间，开始安装。

Java 版本、基础文件共享、校验算法和下载来源切换在默认流程中只作为结果说明，不要求用户决策。

高级展开区允许：

- 指定加载器精确版本。
- 指定已有或托管 Java 构建。
- 修改实例位置。
- 修改隔离策略。
- 查看下载来源和预计空间明细。

从实例创建模板时，界面必须说明模板是一次性快照；由模板新建的实例不会继承模板之后的变化。

强制选择不兼容组合时，界面必须解释已知冲突并允许用户在风险提示后继续。

### 7.5 实例概览与启动

- “启动”始终是页面最突出的主操作。
- 默认账户显示在启动操作附近，临时切换不改变全局账户顺序。
- 首次启动前进行快速完整性检查；发现问题时提供一键修复、切换环境或取消。
- 多实例可同时运行；发现账号、端口或目录冲突时在启动前集中说明。
- 游戏启动后显示实时状态、运行时长、资源占用和安全终止入口。
- 游戏退出后显示正常退出或异常退出、存档备份结果和下一步操作。

### 7.6 资源中心与内容管理

首个预览的在线来源为 Modrinth。资源搜索支持按内容类型、游戏版本、加载器、客户端兼容性和更新时间筛选。

资源详情至少显示：

- 名称、作者、来源、许可证、简介和本地化可用信息。
- 支持的游戏版本与加载器。
- 文件版本、发布日期、下载量和变更记录。
- 必需依赖、可选依赖、冲突和当前实例兼容性。
- 安装目标实例及安装后影响。

安装行为：

- 必需依赖自动纳入同一事务。
- 可选依赖在确认页供用户选择。
- 不允许启动器自行推荐并静默安装额外模组。
- 缺少可信校验值时明确提示风险；用户坚持时允许继续。
- 内容自动更新默认关闭，可按实例开启；开启时说明这会修改实例。
- 单个组件支持锁定版本和忽略更新。

CurseForge 项目在没有可靠官方关联时不得与 Modrinth 项目按名称自动合并。

### 7.7 任务中心

所有长任务统一进入持久化队列。每项任务显示：名称、目标对象、阶段、总体进度、当前速度、剩余估算、来源和可用操作。

阶段应使用用户语言，例如：

- 准备安装。
- 下载游戏文件。
- 验证文件。
- 安装游戏环境。
- 应用加载器。
- 提交更改。
- 创建回滚点。

用户可执行：暂停、恢复、取消、调整优先级、查看详情、复制错误、重试。全局支持限速、暂停全部和计划时段下载。

队列默认依据网络、磁盘和 CPU 压力自动调节并发；用户设置的是上限和计划，而不是必须持续占满的并发数。

进度要求：

- 已知总量时显示确定进度。
- 未知总量时显示阶段活动，不伪造百分比。
- 速度和剩余时间采用平滑值，避免每秒剧烈跳动。
- 自动切换官方源与内置镜像时，在详情中记录，不弹窗打断。
- 自定义源失败时不得静默切换到其他源。

系统重启或异常退出后，发现可恢复任务时询问是否继续；用户拒绝则清理相应临时文件。

### 7.8 账户管理

账户库为全局资源，每个实例可记住默认账户，启动前可临时切换。

账户页面要求：

- 区分 Microsoft、离线和第三方认证账户。
- 清楚显示会话是否有效、上次验证时间和需要重新登录的原因。
- 默认只保存令牌。
- 高级选项可启用本地加密保存第三方账户密码。
- 启用密码保存前说明：密码不会由 MoyuMax 上传，但本地加密不能排除设备入侵或供应链污染风险。
- 主密码只保护查看明文和迁移导出；日常启动可跨重启继续使用已保存凭据。
- 忘记主密码时只提供清除已保存密码，不提供恢复。
- 日志、诊断包和崩溃报告不得展示原始令牌或密码。

### 7.9 Java 环境管理

普通用户不需要进入此页面。安装游戏时，MoyuMax 自动选择并安装 Azul Zulu 兼容构建，环境保存在 MoyuMax 管理的数据位置，不修改系统 Java。

环境页面面向高级用户，展示：

- 发行版、完整补丁版本、架构、位置、健康状态和占用空间。
- 正在引用该环境的实例。
- 验证、设为实例环境、打开位置和删除操作。

同一“发行版、完整补丁版本、架构”只保留一份。删除实例不删除 Java；最后一个引用消失也不自动清理。删除仍被引用的环境时，列出受影响实例并提示风险，用户确认后允许删除。

实例再次启动时若环境缺失，应提供一键恢复或选择其他环境，不得自动装回用户刚删除的构建。

### 7.10 数据、存储与迁移

数据页面展示全局空间占用、各存储位置、移动盘状态、迁移任务、备份和回收站。

- 默认存储位于应用管理目录，用户可分离到其他本地固定磁盘或 USB 存储。
- 不支持 SMB/NAS 作为托管实例位置。
- 移动盘离线时保留实例索引并标记“存储离线”，不得显示为已删除。
- 重新连接后按卷标识恢复，不依赖盘符。
- 一键转移在校验完成前保留原数据；全部匹配后切换数据库索引并删除原文件。
- 索引由数据库维护，不依赖硬链接或符号链接。

空间不足时，界面通知用户并建议清理回收站。提供：

- 清空回收站。
- 从最旧项目开始清理，直到预计空间足够。
- 返回并更改安装或迁移位置。

不得未经同意自动删除回收站内容。

### 7.11 备份与回收站

- 存档默认在游戏启动前和退出后备份。
- 可配置游戏运行期间的定时增量备份间隔和保留数量。
- 世界页面可查看时间线、变更摘要、占用空间并回滚到历史版本。
- 回滚前自动创建当前状态的恢复点。
- 删除实例、世界或其他受管数据时默认进入内置回收站，保留 30 天。
- 永久删除必须显示对象数量、空间和不可恢复说明。

卸载 MoyuMax 时，用户可分别选择保留实例、存档、备份、账户数据和托管 Java。默认建议保留个人数据，选择应在最终确认页再次列明。

### 7.12 日志、崩溃与诊断

实时日志控制台支持暂停滚动、级别筛选、文本搜索、复制、导出和安全终止游戏。

异常退出后生成本地崩溃报告，可能包含：

- 游戏最后输出。
- `latest.log`、`debug.log` 和原生崩溃报告。
- 启动器日志。
- 环境与资源占用信息。
- 脱敏后的启动命令和启动脚本备份。

崩溃页优先显示通俗摘要和建议操作，再提供技术细节。规则化分析可建议可撤销修复，但不得擅自安装模组或修改配置；需要修改时要求用户开启并明确授权。

导出诊断包前展示文件清单和脱敏摘要。账号、用户名、用户目录、服务器地址、令牌和密码必须脱敏。默认不上报，只有用户主动发送时才上传。

游戏无响应时，先询问是否采集线程或进程转储，再允许等待或安全终止。

### 7.13 服务器收藏与端口转发

- 提供全局服务器收藏、状态、延迟和版本检测。
- 用户授权后可将收藏写入指定实例的 `servers.dat`；不得擅自覆盖实例配置。
- 首版可检测 Minecraft 局域网端口并转发到用户指定的本机端口。
- 公网监听默认关闭。
- 开启公网监听时明确说明：服务将可被公网访问；MoyuMax 不配置路由器映射或 Windows 防火墙。
- NAT 类型检测只在用户手动触发后进行，并提前说明会访问外部 STUN 服务和暴露公网 IP。

### 7.14 设置

设置分组：

- 通用：语言、启动行为、关闭行为、通知。
- 下载：并发、限速、计划时段、来源优先级和连接测试。
- 来源：官方优先、镜像优先、自定义源及其校验状态。
- 账户：令牌、密码保险库和主密码。
- Java：默认策略、托管环境和手动环境。
- 游戏：隔离、内存、性能调优和备份默认值。
- 存储：数据位置、迁移、回收站和空间策略。
- 外观：系统、浅色、深色、自定义背景和主题包。
- 无障碍：减少动画、高对比度、字号和键盘辅助。
- 网络：服务器检测、端口转发和 NAT 检测。
- 更新：稳定版或预览版通道；自动更新默认关闭。
- 隐私与诊断：日志保留、诊断导出和遥测状态。
- 开发者：CLI、调试日志和实验能力。
- 关于：版本、许可证、第三方声明、SBOM、签名和更新检查。

设置搜索应能定位到具体设置项，并在跳转后短暂突出目标。修改高影响设置时，在控件附近解释影响范围。

### 7.15 来源设置

默认“官方源优先”。用户可改为“内置镜像优先”或“自定义源”。每个选项旁提供测试按钮，测试结果区分 DNS、连接、TLS、响应状态和延迟。

- 官方源与内置可信镜像可在任务中静默互相切换。
- 自定义源不得切换到任何其他来源。
- 自定义源选项下持续显示上述限制。
- 没有可信校验值的来源需在安装确认中再次提示风险。

### 7.16 更新与降级

- 默认只检查并提示启动器更新，不自动下载或安装。
- 首版不提供静默自动下载或安装开关；每次更新都由用户明确触发。
- 稳定版为默认通道；预览版标明稳定性和数据兼容风险。
- 更新或数据迁移失败必须自动回滚。
- 从预览版降级前检查数据兼容性并创建快照；不兼容时阻止直接降级并解释可选路径。

### 7.17 开发者 CLI

CLI 入口只在开发者设置启用后出现，并展示能力边界和风险。

GUI 可提供命令示例、复制按钮和结构化输出预览。所有写操作支持 `dry-run`，使用版本化 JSON、稳定退出码和进度事件。CLI 不得读取凭据、永久删除数据或修改安全设置。

### 7.18 游戏性能建议

- 游戏性能自动调优是后续增强能力，首个预览只提供本地规则化建议和明确授权后的修改。
- 建议功能默认关闭，首次出现相关问题时按需说明，不占用首次运行引导。
- 启用后，用户可以选择仅查看建议，或授权 MoyuMax 修改指定实例的内存、JVM 参数或受支持配置。
- 应用前展示旧值、新值、依据、作用范围和撤销方式，并创建恢复点。
- 未经授权不得改动用户配置；无论是否启用建议，都不得擅自安装性能模组。

## 8. 关键端到端流程

### 8.1 首次安装并启动游戏

1. 用户打开 MoyuMax，看到可交互首页。
2. 用户选择“安装第一个游戏”。
3. 系统推荐稳定版本，用户可直接继续。
4. 用户确认实例名称和预计空间。
5. 任务中心依次展示游戏下载、验证、环境安装和提交。
6. 成功后首页主操作变为“启动”。
7. 需要账户时就地引导登录，不丢失安装上下文。
8. 游戏退出后显示会话与备份结果。

### 8.2 安装模组

1. 用户从实例内容页或资源中心搜索模组。
2. 系统自动使用目标实例版本和加载器过滤。
3. 详情页展示兼容性、来源、许可证和依赖。
4. 用户确认目标实例和可选依赖。
5. 必需依赖与模组进入同一事务。
6. 失败时恢复到安装前状态并给出可执行建议。

### 8.3 更新实例内容

1. 用户主动检查更新，或实例已开启自动更新提示。
2. 系统列出变更、依赖影响、锁定项和潜在冲突。
3. 用户选择逐项或批量处理冲突。
4. 系统创建回滚点并执行更新。
5. 失败时自动恢复完整可启动状态。

### 8.4 崩溃恢复

1. 游戏异常退出。
2. MoyuMax 显示崩溃摘要、可能原因和受影响范围。
3. 用户可查看证据、应用可撤销修复、导出脱敏诊断包或再次启动。
4. 若执行修复，先创建快照；无用户授权不得安装模组或改配置。

### 8.5 数据移动

1. 用户选择目标本地存储并看到峰值空间预估。
2. 后台复制并校验文件，原位置保持可用。
3. 校验通过后原子切换数据库索引。
4. 确认新位置可用后删除原文件。
5. 失败时继续使用原位置，并保留可重试信息。

## 9. 状态、反馈与错误规范

### 9.1 页面必须覆盖的状态

每个有数据依赖的页面在 mockups 和实现中至少覆盖：

- 初始加载。
- 正常有数据。
- 空状态。
- 离线但有本地数据。
- 存储离线。
- 部分数据失败。
- 完全失败。
- 无权限或安全策略阻止。
- 后台状态变化后的刷新。

### 9.2 错误文案结构

错误信息按以下顺序组织：

1. 简短结论，例如“实例未安装完成”。
2. 数据影响，例如“原有实例未被修改”。
3. 推荐操作，例如“重试未完成文件”。
4. 次要操作，例如“查看详情”“复制诊断信息”。
5. 技术错误码，默认折叠。

不得只显示异常类名、HTTP 状态码或“未知错误”。

### 9.3 危险操作分级

- 可撤销操作：普通确认或操作后 Toast 撤销。
- 有恢复点但影响较大：确认页展示影响对象和恢复点。
- 不可恢复操作：要求明确确认，主按钮使用具体动词，如“永久删除 3 个世界”。
- 安全风险授权：说明风险、默认建议和作用范围；用户坚持后允许继续。

风险提示不得使用预勾选框，不得通过弱化文字诱导用户同意。

## 10. 视觉与交互约束

### 10.1 主题

- 支持跟随系统、浅色和深色。
- 支持自定义静态、视频或动画背景。
- 支持第三方纯数据主题包。
- 主题仅能覆盖受限设计令牌和本地资源，禁止任意 CSS、脚本、布局和安全控件覆盖。
- 禁止主题和语言包引用远程图片、字体或视频。
- 动态背景在窗口隐藏、游戏运行、系统节能、减少动画开启或资源超限时暂停并释放资源。

### 10.2 排版与密度

- 默认使用本地系统字体，不捆绑或远程加载非必要字体。
- 文本允许至少 200% 缩放，不截断关键操作。
- 默认采用舒适密度；高级用户可切换紧凑密度，但危险操作的点击区域不得缩小。
- 不把文字烘焙进图片。
- 状态不得只依赖颜色表达，必须有文本、图形或语义补充。

### 10.3 动效

- 动效用于解释层级、状态变化和任务连续性，不用于装饰性拖延。
- 常规界面过渡建议 120–200 ms；复杂页面切换不超过 250 ms。
- 开启系统“减少动画”时移除位移、缩放和连续背景运动，只保留必要淡入淡出。
- 进度动画不得造成布局抖动。

### 10.4 响应式窗口

- 最低支持 1080p 环境和 Windows 系统缩放。
- 定义最小可用窗口尺寸；低于推荐宽度时优先收起次要栏，不隐藏主操作。
- 页面不依赖横向滚动完成核心任务。
- 弹窗在小窗口中可转为全高页面，但需保留返回语义和焦点顺序。

## 11. 无障碍要求

首个公开预览必须完成以下验收：

- 全流程可仅使用键盘操作，焦点顺序符合视觉顺序。
- 所有控件具有可被屏幕阅读器理解的名称、角色、状态和错误关联。
- 焦点指示始终可见，不因主题或背景失去对比度。
- 支持 Windows 高对比度模式和系统文本缩放。
- 支持系统减少动画设置。
- 图表、进度和资源占用提供文本等价信息。
- Toast 和动态错误通过适当的无障碍实时区域播报，但不重复打断。
- 快捷键不会与文本输入或辅助技术常见命令冲突。

安全关键文案、凭据提示、签名验证、删除确认和风险提示由内置受信资源提供，社区语言包不得覆盖。

## 12. 性能体验预算

基准设备：Windows 10 22H2、4 核 CPU、8 GB 内存、SATA SSD、1080p。

- 首个可见窗口 P95 不超过 500 ms。
- 冷启动完全可操作 P50 不超过 1 秒，P95 不超过 2 秒。
- 托盘唤醒主窗口 P95 不超过 250 ms。
- 前台所有 MoyuMax 相关进程总私有内存目标不超过 180 MiB，硬上限 256 MiB。
- UI 卸载后的后台目标不超过 80 MiB，硬上限 120 MiB。
- 在线请求不得阻塞主界面进入可操作状态。
- 滚动、窗口缩放和日志追加不得持续阻塞输入。
- 日志和长列表必须采用虚拟化或等效机制，不能随条目数量线性拖慢界面。

动态背景、Web 内容或第三方主题必须计入同一全进程预算，不能作为排除项。

## 13. 隐私与安全体验

- 遥测、崩溃上传、NAT 检测、公网监听和自动更新均默认关闭。
- 任何联网操作都应能从上下文判断其目的；敏感联网行为需要主动触发。
- 诊断导出前允许预览并说明脱敏内容。
- 自定义来源、未验证文件和不兼容组合通过风险提示后允许继续，但将决定记录在本地任务历史中。
- 公开构建在“关于”和更新详情中展示 Authenticode 状态、包签名验证、SHA-256、SBOM 和来源证明入口。
- 未签名构建明确标记为开发构建，不得伪装成正式发行版。
- 第三方数据主题包和语言包安装前展示来源、权限边界和本地资源清单。

## 14. 国际化

- 内置简体中文、繁体中文和英文。
- 日期、时间、数字、文件大小和复数遵循当前语言区域格式。
- 布局至少为英文文本预留 30% 扩展空间。
- 社区语言包为纯数据格式，具有格式版本、语言标识、作者和完整性信息。
- 缺失翻译回退到英文，再回退到简体中文；不得显示原始资源键给普通用户。
- 搜索设置时可同时匹配当前语言和内置英文关键字。

## 15. 整合包交互原则

- MoyuMax 原生整合包格式公开、版本化、严格声明式。
- 禁止安装脚本和任意代码执行。
- 导入前展示实例内容、来源、许可证、覆盖范围和冲突。
- 冲突集中汇总，支持逐项或批量选择。
- 导出默认只写入资源下载清单，不直接打包可能禁止再分发的模组文件。
- 只有在来源元数据或用户提供的许可证证据明确允许再分发时，才允许嵌入资源文件。
- 无法确认许可证时使用清单引用，并在导出结果中列出未嵌入项目及原因。

## 16. BDD 开发流程

### 16.1 工作方式

每个可见功能均遵循“发现、开发、交付”三阶段：

1. 发现：从本需求书和 mockups 提取用户故事、业务规则、示例和未决风险。
2. 开发：先写失败的端到端行为场景，再由外向内使用 TDD 实现最小功能。
3. 交付：在目标 Windows 基准环境执行行为场景、无障碍检查和性能检查，形成可追踪证据。

单人开发时仍保留三种视角：

- 产品视角：行为是否解决用户任务，是否符合本需求书。
- 开发视角：状态、事务、兼容性和失败路径能否实现。
- 测试视角：边界、恢复、并发、离线和无障碍是否可验证。

### 16.2 Feature 文件约定

- 可执行场景计划存放于 `features/ui/`，使用 UTF-8 和 `# language: zh-CN`。
- 一个 Feature 描述一个用户能力，不按页面组件拆分。
- 场景描述业务行为，不写 CSS 选择器、线程等待或内部类名。
- 每个场景具有稳定标签，例如 `@UI-INSTALL-001`，用于关联需求、自动化测试和发布证据。
- 数据组合和算法细节使用单元测试覆盖，不在 Gherkin 中穷举。

### 16.3 Definition of Ready

功能进入实现前必须满足：

- 用户价值和作用范围明确。
- 主路径、空状态、失败路径和恢复路径已有示例。
- mockup 已覆盖关键状态，或该功能明确属于无视觉后台能力。
- 隐私、安全、无障碍和性能影响已识别。
- 至少一个端到端场景可先写成失败测试。

### 16.4 Definition of Done

功能只有同时满足以下条件才可称为 validated：

- BDD 场景在目标 Windows 环境通过。
- 相关单元、集成和组件测试通过。
- 键盘、屏幕阅读器、缩放、高对比度和减少动画检查通过。
- 失败、取消、恢复和重启路径已有验证证据。
- 性能预算没有回归，或偏差已有明确批准。
- 需求、场景和实现之间可追踪。
- 文档与实际行为一致。

代码已写但未完成上述验证时，只能称为 implemented，不能称为 validated 或 completed。

## 17. 核心 BDD 验收场景

以下场景是产品级验收基线。实现阶段应拆分为独立 Feature 文件，并补充底层单元和集成测试。

```gherkin
# language: zh-CN
@UI-STARTUP-001
功能: 快速进入可操作首页
  场景: 在线服务响应缓慢时启动应用
    假如 本地已有一个可启动实例
    而且 在线更新与资源服务暂时没有响应
    当 用户启动 MoyuMax
    那么 应先显示可操作的本地首页
    而且 用户可以立即启动本地实例
    而且 在线状态刷新不得阻塞主界面

@UI-INSTALL-001
功能: 零门槛安装游戏
  场景: 新用户使用默认选项安装推荐版本
    假如 用户没有安装系统 Java
    而且 MoyuMax 中没有任何实例
    当 用户选择安装推荐稳定版并确认
    那么 游戏和兼容的托管 Java 应进入同一安装任务
    而且 界面应显示“安装游戏环境”阶段
    而且 用户不需要选择 JDK 或修改系统环境变量

@UI-INSTALL-002
功能: 原子安装与恢复
  场景: 安装过程中网络中断
    假如 游戏文件正在下载到暂存区
    当 网络连接中断
    那么 现有实例和共享基础文件不得变为不可启动状态
    而且 任务应显示可恢复原因
    当 用户恢复任务
    那么 系统应先校验可续传内容
    而且 无法续传的对应内容应清理后重新下载

@UI-JAVA-001
功能: Java 环境全局去重
  场景: 两个实例需要同一完整 Java 构建
    假如 一个实例已安装指定发行版、补丁版本和架构的 Java
    当 用户安装另一个需要相同构建的实例

    而且 任务不得再次下载或安装相同构建

功能: 删除正在使用的 Java

    当 用户选择删除该环境
    那么 界面应列出两个受影响实例并提示不建议删除
    当 用户确认承担风险
    那么 系统应允许删除
    而且 下次启动受影响实例时应提供恢复或切换环境

@UI-INSTANCE-001
功能: 默认实例隔离
  场景: 创建新实例

    而且 可校验重建的基础文件可以共享

@UI-INSTANCE-002
功能: 关闭实例隔离
  场景: 用户坚持关闭隔离
    假如 实例当前使用推荐的完全隔离
    当 用户关闭隔离
    那么 界面应说明实例相互污染和损坏风险
    当 用户确认继续
    那么 系统应应用选择并记录影响范围

@UI-TASK-001
功能: 异常退出后的任务恢复

@UI-SOURCE-001
功能: 下载来源故障切换
  场景: 官方优先模式下官方源不可用
    假如 用户选择“官方源优先”
    而且 内置可信镜像可用
    当 官方源下载失败
    那么 任务可以静默切换到内置可信镜像
    而且 切换记录应可在任务详情查看

  @UI-SOURCE-002
  场景: 自定义源不可用
    假如 用户选择了自定义源
    当 自定义源下载失败

@UI-MOD-001
功能: 安装模组及依赖
  场景: 模组包含必需和可选依赖

    而且 该模组有一个必需依赖和一个可选依赖
    当 用户进入安装确认

    而且 可选依赖应由用户选择
    当 安装事务失败
    那么 实例应恢复到安装前状态

@UI-UPDATE-001
功能: 实例内容更新默认关闭
  场景: 新建实例后发现模组更新

    那么 系统只能提示更新可用
    而且 不得下载或修改实例内容

@UI-ACCOUNT-001
功能: 本地密码保险库风险告知
  场景: 用户启用保存第三方账户密码

    那么 界面应说明本地加密的能力边界和供应链风险
    而且 默认选择应保持为不保存密码
    当 用户确认启用并设置主密码

@UI-STORAGE-001
功能: 移动存储离线

    而且 系统不得将实例标记为已删除或损坏

@UI-STORAGE-002
```

## 18. 可用性与发布验收

每个公开预览里程碑至少执行一轮以新手为主的任务测试。首个预览建议以 5 名未参与开发的 Windows 用户进行形成性测试，重点不是统计显著性，而是发现阻塞问题。

核心任务：

1. 从空状态安装推荐版本并启动。
2. 为实例安装一个带依赖的 Modrinth 模组。
3. 找到失败任务原因并恢复。
4. 从回收站恢复误删实例。
5. 导出脱敏崩溃诊断包。

发布门槛：

- 核心任务完成率 100%，不得存在阻塞性引导缺失。
- 用户无需外部教程理解主路径。
- 不发生不可恢复数据丢失。
- 严重无障碍阻塞为 0。
- 性能指标满足第 12 节预算。

## 19. 关键文案基线

以下文案表达的是必须传达的含义，mockups 可调整措辞但不能删减信息：

### 19.1 关闭隔离

“关闭隔离会让多个实例共享可变文件，模组、配置或存档可能相互影响。建议保持隔离。你仍可继续，但请先确认受影响的实例。”

### 19.2 保存第三方账户密码

“MoyuMax 只会在本地加密保存密码，不会主动上传密码。但本地加密无法完全防御设备入侵、同用户恶意程序或供应链污染。默认只保存登录令牌。”

### 19.3 公网监听

“开启后，该端口可以绑定公网接口并可能被互联网访问。MoyuMax 不会配置路由器端口映射或 Windows 防火墙，请自行确认网络安全。”

### 19.4 未验证内容

“此来源没有提供可验证的可信校验值，文件完整性无法得到充分确认。建议取消并更换来源。若继续，MoyuMax 会记录本次决定但不再拦截安装。”

### 19.5 强制删除 Java

“此 Java 环境仍被实例使用。删除后，这些实例将无法直接启动，直到恢复或选择其他环境。删除实例本身不会自动删除 Java。”

## 20. Mockup 交付清单

每个页面或流程的 mockups 应同时提供：

- 默认、有数据、空、加载、离线、部分失败和完全失败状态。
- 主要操作、次要操作、危险操作和禁用原因。
- 弹窗、Toast、Banner 和系统通知的使用位置。
- 键盘焦点顺序、默认焦点和弹窗关闭后的焦点返回。
- 100%、150%、200% 缩放下的关键布局。
- 简体中文、繁体中文和英文长文本适配。
- 浅色、深色、高对比度和自定义背景下的可读性。
- 减少动画开启时的替代行为。
- 长实例名、长路径、大任务队列和大量日志时的极端数据状态。
- 所属 BDD 场景标签。

## 21. 已确定的风险与处理原则

- Web UI 的技术可行性不能以牺牲冷启动和内存预算为代价；技术栈选择需通过原型基准验证。
- Windows 11 ARM64 仅作为 x64 仿真兼容目标，在实机验证前不宣称正式支持。
- WSL 只验证核心与 CLI，不能作为 Linux 桌面支持证据。
- CurseForge provider 保留接口但默认禁用，取得合规 API 授权后再启用。
- 自定义来源和不兼容组合允许用户在充分告知后强制继续，事务和诊断能力仍不可绕过。
- 游戏性能自动调优是愿景；启动器低占用和稳定性是首发硬指标。
- 整合包资源再分发遵守许可证：默认导出下载清单，许可证明确允许时才嵌入文件。
- 云服务未来可以收费，但本地基础功能、数据访问和完整离线使用不得受订阅影响。

## 22. 追踪规则

需求、设计、实现和验收使用同一稳定标识：

`需求条目 -> Mockup 标注 -> Gherkin 标签 -> 自动化测试 -> 发布验证证据`

任何行为变更应先修改示例和需求，再修改实现。若实现与需求书不一致，必须明确记录为需求变更、已批准偏差或缺陷，不能以当前实现反向覆盖产品意图。
